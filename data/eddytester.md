⚡️ Кэширование в API: Шпаргалка для QA

Кэширование - это сохранение копии ответа сервера, чтобы при следующем запросе не тратить время на долгие вычисления или походы в базу данных.

🔍 Два главных состояния (из словаря профи)

🔘Cache HIT (Попадание)
Данные нашлись в кэше. Ответ прилетел мгновенно.

🔘Cache MISS (Промах)
В кэше пусто. Сервер идет в базу данных, берет данные и по пути «закидывает» их в кэш для следующего раза.

💻 Как это выглядит в коде
Программист пишет простую логику:

Мой любимый сканер.

F Дуршлаг

X-Frame-Options: Если его нет (красное), твой сайт можно встроить в невидимый фрейм и красть клики юзеров (Clickjacking)

Чем HTTP 1.1 лучше HTTP 1.0

Пара интересных различий которые я узнал сегодня:

1. Постоянные соединения Persistent Connections
В HTTP 1.1 по умолчанию используются постоянные соединения, что позволяет производить несколько последовательных запросов и ответов в рамках одного TCP соединения.

2. Конвейерная обработка запросов 
Request Pipelining
В HTTP 1.1 возможно отправлять несколько запросов на сервер без ожидания ответа на каждый запрос.
Это позволяет уменьшить задержку и повысить эффективность коммуникации между клиентом и сервером.

Решение
Impact Analysis как раз является способом эти недосказанности предотварить. 
Для каждого сервиса описываются зоны его влияния: какие блоки продукта он напрямую затраги
