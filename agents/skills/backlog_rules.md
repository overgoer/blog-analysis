# Skill: backlog-rules

## Статусы задач (только 4)
- **pending** — новая, не начата
- **in_progress** — в работе (кто-то занят)
- **done** — завершена
- **blocked** — заблокирована другой задачей (указать причину)

НЕ использовать: `active`, `waiting`, `hold`, `backlog` и другие кастомные статусы.

## Приоритеты
- **P0** — критично, блокирует всё. Таких не больше 2.
- **P1** — важно, делать в этом спринте.
- **P2** — средний приоритет, делать когда есть время.
- **P3** — хотелка, "когда-нибудь" (конкурентный анализ, посты-заготовки).

## Формат задачи
```
backlog add P2 [TAG] Описание задачи
```
Где `[TAG]` — один из: `[DEV]` (код), `[BSA]` (сам Bizzy), `[EDDY]` (нужен Эдди), `[BUG]` (баг), `[POST]` (контент). TAG необязателен.

## Правила
1. Не создавай тестовые задачи — только реальные.
2. Перед добавлением проверь, нет ли уже такой задачи (поиск по описанию).
3. Если задача дублирует существующую — не создавай новую, обнови старую.
4. `done` — только когда реально завершено (код написан/пост опубликован/баг починен).
5. Раз в день проверяй backlog: нет ли зависших `in_progress` (брошенных).
6. При блокировке ставь `blocked` и пиши в описании `blocked_by: B-XXX`.
7. `blocked` задачу НЕ трогать, пока блокирующая не выполнена.
8. В конце недели: P3 done можно архивировать (удалять из активного бэклога).

## Команды backlog tool
- `backlog add P2 Название` — создать задачу
- `backlog done B-001` — завершить
- `backlog ip B-001` — начать работу
- `backlog summary` — сводка по всем
- `backlog delete B-001` — удалить (только если ошибка или дубликат)
